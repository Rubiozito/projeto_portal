# Data Model: User CRUD

**Phase**: 1 — Design & Contracts
**Date**: 2026-05-22
**Feature**: [spec.md](spec.md) · [plan.md](plan.md) · [research.md](research.md)

## Entities

### User

Represents a registered individual in the system.

| Field          | Type            | Required   | Mutable | Description                                                            |
| -------------- | --------------- | ---------- | ------- | ---------------------------------------------------------------------- |
| `id`           | UUID v4 string  | Yes (auto) | No      | Unique identifier, generated at creation                               |
| `name`         | string          | Yes        | Yes     | Full name; min 1 character                                             |
| `email`        | string          | Yes        | Yes     | Valid email; normalized to lowercase; unique across all users          |
| `creationDate` | ISO 8601 string | Yes (auto) | No      | Set by the system at creation; never writable by callers               |
| `role`         | `UserRole`      | Yes        | No      | Assigned at creation; immutable after                                  |
| `companyId`    | string          | No         | Yes     | Optional company reference; any non-empty string; no referential check |

### UserRole

An enumeration of the valid role values a user may hold.

| Value      | Meaning                                        |
| ---------- | ---------------------------------------------- |
| `OWNER`    | Can create and own a company                   |
| `EMPLOYEE` | Can join a company as an employee              |
| `EXTERNAL` | Can join a company as an external collaborator |

## Validation Rules

### Create User (POST)

| Field          | Rule                                                                   |
| -------------- | ---------------------------------------------------------------------- |
| `name`         | Required · string · min length 1                                       |
| `email`        | Required · valid email format · normalized to lowercase before storage |
| `role`         | Required · one of `OWNER`, `EMPLOYEE`, `EXTERNAL`                      |
| `companyId`    | Optional · if present: string · min length 1                           |
| `id`           | Stripped silently — ignored if provided (system-generated)             |
| `creationDate` | Stripped silently — ignored if provided (system-generated)             |
| Unknown fields | Stripped silently                                                      |

### Update User (PATCH)

| Field          | Rule                                                                                  |
| -------------- | ------------------------------------------------------------------------------------- |
| `name`         | Optional · string · min length 1                                                      |
| `email`        | Optional · valid email format · normalized to lowercase                               |
| `companyId`    | Optional · string · min length 1; supply `null` to clear                              |
| `role`         | Stripped silently (immutable — never causes error)                                    |
| `id`           | Stripped silently                                                                     |
| `creationDate` | Stripped silently                                                                     |
| Body empty     | Rejected with HTTP 400 — at least one of `name`, `email`, `companyId` must be present |
| Unknown fields | Stripped silently                                                                     |

### UUID Path Parameter (`:id`)

| Rule                           |
| ------------------------------ |
| Must be a valid UUID v4 string |
| Invalid format → HTTP 400      |

## State Transitions

```
         [creation request]
               │
               ▼
         ┌──────────┐
         │  Active  │──── PATCH /users/:id ───► (name / email / companyId updated)
         └──────────┘
               │
         DELETE /users/:id
               │
               ▼
         ┌──────────┐
         │ Deleted  │  (no soft-delete; record removed from store)
         └──────────┘
```

- `id`, `creationDate`, and `role` are frozen at creation.
- There is no intermediate state; deletion is permanent.

---

## Uniqueness Constraints

| Field                          | Scope              | Behaviour on violation                                     |
| ------------------------------ | ------------------ | ---------------------------------------------------------- |
| `email` (lowercase-normalised) | Global (all users) | HTTP 409 Conflict                                          |
| `id`                           | Global             | Generated by system — no user-triggered collision possible |

## Zod Schemas (non-normative sketch)

```ts
// Create
export const CreateUserSchema = z.object({
  name: z.string().min(1),
  email: z.string().email().toLowerCase(),
  role: z.enum(['OWNER', 'EMPLOYEE', 'EXTERNAL']),
  companyId: z.string().min(1).optional(),
});

// Update (PATCH) — role/id/creationDate stripped by .strip() default
export const UpdateUserSchema = z
  .object({
    name: z.string().min(1).optional(),
    email: z.string().email().toLowerCase().optional(),
    companyId: z.string().min(1).nullable().optional(),
  })
  .refine((data) => Object.values(data).some((v) => v !== undefined), {
    message: 'At least one field must be provided',
  });

// Path param
export const UuidParamSchema = z.object({
  id: z.string().uuidv4(),
});
```

## Decisions & Rationale

| Decision                                     | Rationale                                                                               |
| -------------------------------------------- | --------------------------------------------------------------------------------------- |
| `creationDate` stored as ISO 8601 string     | Portable, JSON-serializable, no Date object serialization edge cases                    |
| `role` as TypeScript `enum` + Zod `z.enum()` | Explicit allowed values; easy to extend when company module arrives                     |
| `companyId` as opaque string                 | Company module not yet defined; format constraint deferred (see spec Clarifications Q5) |
| `companyId` nullable on update               | Allows explicitly clearing the association via `null`                                   |
| Email stored lowercase                       | Case-insensitive uniqueness without runtime collation (FR-014)                          |
